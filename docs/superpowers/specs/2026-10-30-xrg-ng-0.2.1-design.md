# XRG-ng 0.2.1 — unified release, Mac distribution, Windows groundwork

Status: for user review. Baseline: `main` at `e168a89`.

## Goal

Ship XRG-ng 0.2.1 for macOS and Linux as one version, add the Mac distribution
channels the user's other apps have (Sparkle, Homebrew, donations), and lay the
build seams that make the 0.3.0 Windows port cheaper. No new monitoring features.

## Roadmap context (not in scope here)

- 0.3.0: Windows port reusing shared Swift and Rust/egui; UX/UI parity so every
  platform feels like the macOS app, Liquid Glass included.
- 0.4.0: desktop-pinned widgets (Rainmeter-like); menubar icon, Dock icon, or both.

## Decisions already made

- One version for all platforms from 0.2.1 on; plain `vX.Y.Z` tags. Existing
  `v0.1.0` and `linux-v0.2.0` tags and releases stay as they are.
- Feature freeze: Codex's handoff steps 1–4 (sampling/lifecycle parity, hidden
  optional-source eligibility, unprivileged RKNPU access, PLATFORM_PARITY items)
  wait until after 0.2.1.
- Windows prep is option B: compile-only seams and CI; no Windows product.
- Donations via GitHub Sponsors, no launch prompts (Tesserae pattern).
- GLM-5.3 implements, Codex reviews, Claude coordinates.

## Work items

### 1. Unified version 0.2.1

- Xcode app/framework/test `MARKETING_VERSION` 0.2.1, `CURRENT_PROJECT_VERSION` 2;
  `latest_version.txt` 0.2.1; `xrg-linux/rust/Cargo.toml` + lockfile 0.2.1.
- A single check (script or test) fails when these disagree.
- `RELEASING.md` rewritten for one release per version: macOS and Linux assets on
  one GitHub release, tag `vX.Y.Z`, Linux signing flow kept.
- Linux CI's real upgrade check moves to 0.2.0 → 0.2.1 (frozen previous app).
- `releases/0.2.1.md` notes covering both platforms' changes since their last
  releases.

### 2. Sparkle on macOS

- Add Sparkle 2 (latest 2.x, SwiftPM) to the app target; `SUFeedURL`,
  `SUPublicEDKey`, automatic checks on by default with the standard prompt.
- New EdDSA key in the login Keychain, account `XRG-ng`. Public key in Info.plist;
  private key never leaves the Keychain.
- XRG-ng → Check for Updates… menu item.
- Appcast: `docs/appcast.xml` on `main`, served by GitHub Pages from `main:/docs`
  (Pages is NOT enabled yet; enabling it is a publish step needing the user's OK).
- `Tools/release-macos.sh` gains: Sparkle-sign the notarized DMG/ZIP, emit the
  appcast item (version, build, minimum macOS 26, length, signature, notes link).
- Sparkle's licence added to THIRD_PARTY_NOTICES and the in-app notices.

### 3. Homebrew cask

- `Casks/xrg-ng.rb` in `sdelavega/homebrew-tap` (local `~/src/homebrew-tap`):
  DMG url, sha256, `depends_on macos: ">= :tahoe"`, `auto_updates true`, zap paths.
- A publish script updates the cask from the release's checksums. Committing and
  pushing the tap happens only at publish, with the user's OK.

### 4. Donations

- `.github/FUNDING.yml` (`github: sdelavega`).
- macOS: Help (or app) menu "Support XRG-ng…" opening GitHub Sponsors.
- Linux: the same link in the egui About/Help surface if one exists; otherwise
  README only.
- README section matching Tesserae's wording, adapted.

### 5. Windows groundwork (compile-only)

- Rust: gate Linux-only collectors/IO (procfs, sysfs, zbus, X11/Wayland window
  code) behind `cfg(target_os = "linux")` modules with a platform trait/module
  boundary; Windows gets stubs that report "unavailable", never invented data.
  Feature flags so `cargo check --target x86_64-pc-windows-msvc` succeeds for the
  crate (UI included where eframe allows).
- Shared Swift core (`Shared/`): confirm it builds with Swift for Windows; fix
  Darwin/Glibc-only imports behind `#if canImport`.
- `build.rs`: Windows library naming for the Swift dynamic library.
- CI: `windows.yml` job on `windows-latest` runs the compile checks (and shared
  Swift tests if they run). One local confirmation run on `madrid` (or
  `barcelona`) over SSH.
- `docs/WINDOWS_PORT.md`: what compiles, which collectors need Windows
  implementations (PDH/WMI/DXGI/etc.), packaging options, and the 0.3.0 parity
  plan outline. Linux and macOS behaviour unchanged (full gates prove it).

### 6. Release preparation and gate (no publishing)

- Full `Tools/ci-macos.sh Release` (native ARM + Rosetta, packaged smokes).
- `Tools/ci-linux.sh` on x86-64 (Docker on the Mac or madrid WSL) and natively on
  pamplona (RK3588) and salamanca (Pi 5); boards may get toolchains installed.
- Release candidate build: signed/notarized DMG+ZIP with dSYMs retained (UUIDs
  matching), appcast item, cask diff, signed Linux packages from CI run.
- Publishing (tag, GitHub release, Pages, appcast push, tap push) only after the
  user says so.

## Global constraints

- Work on branch `release/0.2.1` in `/Volumes/MacStorage/src/XRG` (no worktrees
  elsewhere on the volume). No other `/Volumes/*` paths.
- Use Codex's `Tools/ci-macos.sh` / `Tools/ci-linux.sh` flow; change it only with
  a demonstrated improvement that the reviewer accepts. Never weaken assertions or
  smoke gates.
- Preserve settings, XTF load/save, nib compatibility, source attribution,
  GPL-3.0-or-later notices, missing-data honesty.
- No secrets, home paths or private hostnames/addresses in commits. Never print the
  environment. No sudo on the Mac; sudo on salamanca/pamplona allowed.
- Cleanup after every task: build roots in a per-task scratch dir; delete what the
  task created (DerivedData, $TMPDIR, test prefs, Docker containers/images/build
  cache it made, remote scratch); report paths and bytes freed.
- Ask before any push, tag, release, Pages change or tap commit.

## Review focus (for Codex)

- Version consistency across Xcode, Cargo, latest_version, tags and notes.
- Sparkle: key handling (no private key in repo/logs), appcast correctness,
  signature over the exact shipped archive, hardened-runtime/entitlements intact.
- Windows seams: Linux behaviour unchanged, stubs report unavailable, no `cfg`
  leaks that silently drop Linux features.
- Release scripts: idempotent, refuse dirty trees/mismatched commits.
- Cleanup performed and reported.

## Success criteria

- `release/0.2.1` has all items, every task reviewed by Codex.
- Full macOS gate and Linux gate (x86-64 + both ARM boards) pass; Windows compile
  job passes on CI and on madrid/barcelona.
- Release candidate artifacts verified locally; nothing published without the
  user's OK.
