# XRG-ng 0.2.2 (draft)

Draft notes for the next release; sections fill in as changes land.

## macOS

- **AI log scanner.** A log file rewritten to the same size is now re-read,
  so token totals, model attribution and continuity follow the new content.
  Previously the scanner compared only the modification date, size, inode and
  device, so a rewrite that kept or restored the modification date, or one
  that landed within the same timestamp tick, could go unnoticed. The scanner
  now also compares the change time (ctime), which writers cannot set back,
  and trusts unchanged metadata only for a snapshot taken more than 3 seconds
  after the file's last modification or change time. A recently written file
  is therefore read again on the next scan, and an unchanged file is not
  re-read after that.

## Linux

- **AI log scanner.** A log file rewritten to the same size within the
  filesystem's timestamp granularity is now re-read, so token totals, model
  attribution and continuity follow the new content. Previously such a
  rewrite could go unnoticed on filesystems with coarse timestamps (observed
  on Raspberry Pi 5, in 4 ms steps). The scanner still trusts unchanged
  metadata, but only for a snapshot taken more than 3 seconds after the
  file's last modification or change time. A recently written file is
  therefore read again on the next poll, and an unchanged file is not
  re-read after that.
